# Ошибки и отладка

После урока вы сможете находить синтаксические, исполнительные и логические ошибки.

> **Фокус**
> - Нужно знать: три основных типа ошибок.
> - Нужно уметь: читать последнюю строку сообщения Python и находить место расхождения.
> - Полезно знать: маленький тест с известным ответом полезнее случайных изменений кода.

## Ошибка сообщает, что пошло не так

Синтаксическая ошибка означает, что Python не смог разобрать программу. Ошибка выполнения возникает уже во время работы. Логическая ошибка не обязательно вызывает сообщение: программа может завершиться, но дать неверный ответ.

```python
number = int(input())
print(10 / number)
```

Если ввести текст вместо числа, проблема возникнет при `int`. Если ввести `0`, деление завершится `ZeroDivisionError`.

## Как читать сообщение

Обычно сначала полезно посмотреть на последнюю строку traceback: там указан тип ошибки. Затем найти строку своей программы и проверить значения, с которыми она выполнялась.

Для логической ошибки уменьшите пример и проследите состояние вручную.

```python
numbers = [2, 5, 8]
total = 0

for_number = numbers[0]
total = for_number
for_number = numbers[2]
total = for_number
print(total)
```

Здесь программа не падает, но видно главное расхождение: новое значение заменяет накопленное вместо добавления. В реальной задаче такой дефект ищут трассировкой значений после каждого шага.

## Алгоритм отладки

1. Зафиксируйте ожидаемый результат.
2. Посмотрите фактический результат или тип ошибки.
3. Найдите первую строку, после которой состояние стало неверным.
4. Проверьте простой и граничный тест.
5. Исправляйте найденную причину, а не случайную строку.

## Частые ошибки

- менять код наугад, не читая сообщение;
- проверять только один удобный пример;
- искать проблему только в последней строке;
- не проверять граничные значения;
- оставлять временный отладочный вывод в окончательном решении.

## Проверьте себя

1. Чем логическая ошибка отличается от ошибки выполнения?
2. Где обычно указан тип исключения?
3. Зачем уменьшать входные данные?
4. Что такое граничный тест?
5. Почему важно найти первый неправильный шаг?

## Перед практикой

Не начинайте с исправления. Сначала сформулируйте, что программа должна делать, и найдите первый шаг, где фактическое состояние расходится с ожидаемым.
