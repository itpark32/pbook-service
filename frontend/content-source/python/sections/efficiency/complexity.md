# Оценка сложности

После урока вы сможете оценивать число операций и выбирать подходящий алгоритм.

> **Фокус**
> - Нужно знать: важен рост числа действий при увеличении размера входа.
> - Нужно уметь: различать один проход, вложенный перебор и деление диапазона пополам.
> - Полезно знать: оценка сложности нужна до запуска на больших данных.

## Один проход

```python
numbers = [4, 1, 7, 3]
maximum = numbers[0]

for number in numbers:
    if number > maximum:
        maximum = number

print(maximum)
```

Если список становится в два раза длиннее, число проверок тоже растёт примерно в два раза. Это линейный рост — порядок `O(n)`.

## Вложенный перебор

```python
numbers = [1, 2, 3, 4]
pairs = 0

for first in numbers:
    for second in numbers:
        if first < second:
            pairs += 1

print(pairs)
```

Два полных вложенных прохода дают примерно `n * n` комбинаций — порядок `O(n²)`.

Для больших `n` разница между `n` и `n²` становится огромной.

## Логарифмический рост

Если алгоритм на каждом шаге отбрасывает примерно половину вариантов, число шагов растёт очень медленно. Так работает двоичный поиск на отсортированных данных.

Оценка сложности не означает точное время в секундах. Она показывает, как меняется объём работы при росте входа.

## Частые ошибки

- считать только количество строк кода;
- считать два последовательных цикла обязательно квадратичными;
- не учитывать вложенность циклов;
- выбирать алгоритм без учёта максимального размера входа;
- путать точное число операций и порядок роста.

## Проверьте себя

1. Почему один полный проход имеет порядок `O(n)`?
2. Почему два вложенных полных прохода дают `O(n²)`?
3. Дают ли два последовательных цикла `O(n²)`?
4. Что означает деление диапазона пополам?
5. Зачем знать ограничения задачи до выбора алгоритма?
