# Последовательности и ввод до стоп-сигнала

После урока вы сможете обрабатывать поток значений и корректно работать со стоп-сигналом.

> **Фокус**
> - Нужно знать: стоп-сигнал завершает ввод и обычно не входит в обрабатываемые данные.
> - Нужно уметь: читать очередное значение, проверять его и обновлять накопители.
> - Полезно знать: порядок «прочитать → проверить → обработать» защищает от случайной обработки стоп-сигнала.

## Последовательность может иметь неизвестную длину

Когда заранее неизвестно, сколько значений придёт, ввод можно завершать специальным значением.

```python
total = 0
number = int(input())

while number != 0:
    total += number
    number = int(input())

print(total)
```

Ноль здесь является стоп-сигналом. Он проверяется до добавления в сумму и поэтому не считается элементом последовательности.

## Важен порядок действий

```python
count = 0
number = int(input())

while number != -1:
    if number > 10:
        count += 1
    number = int(input())

print(count)
```

На каждой итерации текущее значение уже известно, затем оно обрабатывается, после чего читается следующее.

Если сначала добавить значение в накопитель, а потом проверить стоп-сигнал, служебное значение может случайно повлиять на ответ.

## Пустая последовательность тоже возможна

Пользователь может сразу ввести стоп-сигнал. Тогда тело цикла не выполнится ни разу. Алгоритм должен корректно оставить счётчики и суммы в их начальном состоянии.

Для минимума и максимума такая ситуация требует отдельной договорённости: подходящих данных может не быть.

## Частые ошибки

- включать стоп-сигнал в сумму или количество;
- забывать прочитать следующее значение внутри цикла;
- предполагать, что хотя бы один обычный элемент обязательно существует;
- использовать стоп-сигнал, который может быть допустимым элементом по условию;
- обновлять накопители до проверки служебного значения.
