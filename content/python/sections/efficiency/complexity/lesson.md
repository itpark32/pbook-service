# Оценка сложности

После урока вы сможете оценивать число операций и выбирать подходящий алгоритм.

Сложность показывает, как растёт число действий при росте данных, а не точное время в секундах.

> **Фокус**
> - **Нужно знать:** `O(1)`, `O(n)`, `O(n²)`, `O(log n)` на интуитивном уровне.
>
| Алгоритм | Рост | Для 1 000 000 элементов |
|---|---:|---:|
| доступ по индексу | `O(1)` | одно действие |
| линейный поиск | `O(n)` | до миллиона |
| бинарный поиск | `O(log n)` | около 20 |
| двойной полный проход | `O(n²)` | около триллиона |

Константы важны в реальной работе, но сначала сравнивают характер роста. Два последовательных прохода — `O(n)`, а вложенный полный цикл — обычно `O(n²)`. Предварительная сортировка может окупиться, если потом выполняется много быстрых поисков.

## Как читать код

Один цикл по `n` элементам даёт линейный рост. Два последовательных цикла дают `n + n = 2n`, то есть тот же характер `O(n)`. Вложенные полные циклы дают `n · n`. Цикл, который каждый раз делит число или диапазон пополам, выполняется порядка `log n` раз.

Не всякая вложенность означает `n²`: если внутренний указатель за всю программу только движется вперёд и не сбрасывается, общее число шагов может остаться линейным. Считайте фактические движения, а не только отступы.

## Время и память

Алгоритм оценивают и по дополнительной памяти. Потоковая сумма использует `O(1)` памяти, список всех `n` чисел — `O(n)`. Иногда память обменивают на скорость: множество уже встреченных значений ускоряет проверку повторов, но занимает место.

Оценка нужна до реализации: при `n = 100 000` квадратный алгоритм почти наверняка неприемлем, а несколько линейных проходов обычно разумны.

## Мини-практика

1. Оцените один и два вложенных цикла. 2. Сравните поиск для 100 и 1 000 элементов. 3. Объясните преимущество бинарного поиска. 4. Оцените два последовательных прохода. 5. Сравните память потока и списка. 6. Найдите пример вложенного кода не `O(n²)`.

## Практическое правило

Сначала оцените максимальный размер входа. Один проход по миллиону элементов обычно допустим, а полный перебор всех пар даёт уже около триллиона сравнений. Оценка сложности нужна до написания кода, а не после превышения лимита времени.
