# Двоичный поиск

После урока вы сможете искать значение в отсортированном массиве за логарифмическое время.

Линейный поиск проверяет все элементы. Бинарный сравнивает с серединой и каждый раз отбрасывает половину — но требует сортировки.

> **Фокус**
> - **Нужно знать:** границы `left`, `right`, середина.
> - **Нужно уметь:** объяснить, почему поиск завершается.
>
```python
left = 0
right = len(numbers) - 1
target = 42
position = -1

while left <= right:
    middle = (left + right) // 2
    if numbers[middle] == target:
        position = middle
        break
    if numbers[middle] < target:
        left = middle + 1
    else:
        right = middle - 1
```

При неравенстве середину уже проверили, поэтому новая граница сдвигается на один. Для миллиона элементов бинарному поиску нужно около 20 сравнений, линейному — до миллиона.

## Инвариант границ

Перед каждым шагом искомое значение, если оно существует, находится внутри отрезка `left..right`. Если середина меньше цели, вся левая часть вместе с серединой уже не подходит. Поэтому пишут `left = middle + 1`. Без `+1` границы могут перестать сужаться.

| шаг | left | right | middle | значение | действие |
|---:|---:|---:|---:|---:|---|
| 1 | 0 | 5 | 2 | 7 | искать справа |
| 2 | 3 | 5 | 4 | 15 | искать слева |
| 3 | 3 | 3 | 3 | 11 | найдено |

Таблица относится к списку `[2, 4, 7, 11, 15, 20]` и цели 11.

## Когда какой поиск

Один поиск в небольшом несортированном наборе проще выполнить линейно. Сортировать только ради одного запроса часто дороже. Бинарный поиск выгоден, когда данные уже упорядочены или запросов много. Если есть повторы и нужен первый или последний индекс, обычный выход при равенстве недостаточен — границу продолжают сдвигать.

> **Python+**
> Модуль `bisect` выполняет бинарный поиск позиции вставки, но сначала важно понять границы вручную.
>
