# Security review — Phase 23

Проверка проведена для backend API, контентного конвейера и браузерного judge.

| Область | Контроль | Результат |
| --- | --- | --- |
| Авторизация | Роли проверяются на всех teacher/admin маршрутах; преподаватель видит только свои группы и их участников | покрыто integration tests |
| Сессии | Случайный токен 256 бит, в БД хранится SHA-256; cookie `HttpOnly`, `Secure` по умолчанию, `SameSite=Lax` | принято |
| Reset и invite | В БД хранится только хеш токена; reset и teacher-invite одноразовые, student invite можно отозвать/перевыпустить | принято |
| CSRF / Origin | Все изменяющие API-маршруты проходят `protect`; при наличии `Origin` он канонизируется и обязан совпасть с `APP_ORIGIN` | принято |
| Заблокированный пользователь | `currentUser` допускает только статус `active`; уже выданная сессия заблокированного пользователя не работает | принято |
| Rate limiting | Вход, регистрация, восстановление, приглашения и изменяющие действия имеют лимит по IP и действию | принято |
| Контент | Markdown не исполняет HTML; URL c `javascript:`, `data:` и `vbscript:` отклоняются validator и не рендерятся | принято |
| Файлы задач | Validator и файловый harness запрещают выход за рабочую директорию | принято |
| Judge | Worker ограничен пятью секундами и 1 МиБ вывода; после timeout Worker пересоздаётся | принято |
| Секреты платформы | Judge работает в отдельном browser Worker; в его filesystem передаются только fixture-файлы упражнения | принято |

Ограничения модели: Pyodide запускается на устройстве ученика, поэтому это учебная среда, а не серверная песочница для недоверенных платформенных секретов. Production deployment должен задавать HTTPS `APP_ORIGIN` и не устанавливать `COOKIE_SECURE=false`.
