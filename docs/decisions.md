# Решения

## 2026-09-11 — Phase 0: исходное состояние

`pbook-service` был пустым каталогом без Git-репозитория и без существующей реализации. Поэтому Phase 1 начинается с нового, минимального monorepo; пользовательские файлы не удалялись.

## 2026-09-11 — Граница vertical slice

В текущем запуске сначала был создан только урок `python-branches-if-else` с двумя guided exercises и одним checkpoint. Массовый import методички по-прежнему отложен: новые representative lessons добавляются только после закрытия соответствующего judge type.

## 2026-09-11 — Адаптация урока «Условия»

Глава `docs/basics/conditions.md` сохранена по смыслу: добавлены `elif`, порядок ветвей, независимые проверки, составные и вложенные условия, таблица трассировки, типовые ошибки и связь со школьным алгоритмическим мышлением. В соответствии с педагогическим правилом curriculum интерактивная практика ограничена двумя guided exercises и одним checkpoint; шесть мини-задач исходной методички не переносятся как шесть одинаковых coding exercises. Три короткие мини-проверки остаются в тексте урока. Checkpoint использует несколько границ доставки и поэтому проверяет перенос `if / elif / else`, а не буквально повторяет guided examples.

## 2026-09-11 — Coverage для неполного курса

Историческая запись заменена актуальной картой навыков SK01–SK46; details и границы содержатся в `docs/lesson-content-redesign-map.md`.

## 2026-09-11 — Reference solutions

Content validator запускает только доверенные эталонные решения через локальный `python3` во время проверки контента. Backend пользовательский Python не выполняет; учебный код ученика исполняется только в Pyodide Worker в браузере.

## 2026-09-11 — Phase 6: function judge

Function judge исполняет код ученика в Dedicated Pyodide Worker. Для каждого test создаётся новый globals namespace, поэтому значения одного вызова не попадают в другой. Аргументы и возвращаемые значения ограничены JSON-serializable данными; judge сравнивает `return`, а `stdout` сохраняет лишь как диагностическую информацию. Добавлен урок `python-functions-basics` по `docs/functions/basics.md` с двумя guided exercises и checkpoint `sum_digits`.

## 2026-09-12 — Phase 7: files judge

Files judge использует виртуальную файловую систему Pyodide. Для каждого test Python harness создаёт отдельную временную рабочую папку, записывает только заданные input fixtures, запускает исходный код в этой папке, читает ожидаемые output files и удаляет папку. Это изолирует результаты между tests и не даёт относительным путям выйти за рабочую папку. Для student UI добавлены переключаемые видимые примеры файлов: они применяются только к кнопке «Запустить»; «Проверить» всегда использует тестовые fixtures. Добавлен учебный срез `python-files-basics` по `docs/files/basics.md`: чтение чисел, запись `output.txt` и checkpoint с `positive.txt`.

## 2026-09-12 — Phase 8: structural constraints

Structural constraints анализируются встроенным модулем Python `ast` в Dedicated Worker до запуска функциональных tests. Поддержаны `requireFunctions`, `forbidCalls`, `forbidMethods`, `forbidImports` и `requireRecursion`; это педагогические требования, а не механизм безопасности. Добавлены два representative lessons: `python-recursion-basics` с checkpoint `factorial`, который обязан вызвать себя, и `python-algorithms-selection-sort` с checkpoint, запрещающим `sorted()` и `.sort()`.

## 2026-09-12 — Phase 11: server-side authentication

Саморегистрация намеренно не добавлялась: до Phase 12 новые student и teacher появляются только через приглашения. Для первого локального администратора используется пара переменных окружения `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD`; повторный запуск не меняет существующего пользователя. Сессия — случайный непрозрачный токен в `HttpOnly` cookie, а в PostgreSQL сохраняется только его SHA-256 hash. Пароли хешируются Argon2id. Verification и reset токены одноразовые и также хранятся только как hashes; reset дополнительно отзывает все сессии пользователя.

## 2026-09-12 — Phase 12: invitations before full group CRUD

Требование student invite «привязан к группе» нельзя корректно реализовать строковым идентификатором или отложенной связью. Поэтому минимальные `groups` и `group_memberships` добавлены вместе с `invites`: преподаватель может создать только свою группу и выдать или regenerate её единственную активную student invite ссылку. Полный CRUD групп, список участников и их удаление остаются в Phase 13. Teacher invite одноразовый с TTL 7 дней; student invite многоразовый и инвалидируется при revoke/regenerate либо блокировке создавшего его преподавателя. Все приглашения сохраняют только hash токена.

## 2026-09-12 — Phase 13: ownership at the backend boundary

Полный CRUD групп реализован без отдельного service-layer state: каждая mutation и list-запрос сначала подтверждает `groups.teacher_id = current_user.id`. Membership можно удалить только для student; это удаляет лишь строку `group_memberships`, не пользователя и не его будущий cloud progress. Удаление самой группы каскадно удаляет memberships и привязанные student invites, поэтому прежние ссылки не могут присоединить ученика к уже несуществующей группе.

## 2026-09-12 — Phase 14: merge without overwriting code

Progress хранится отдельно по exercise и lesson. Сервер сам инкрементирует attempts только в endpoint проверки и никогда не сбрасывает completed после неудачи. При переносе guest progress completion объединяется через OR, но два разных непустых текста кода вызывают `409 progress_conflict`; до явного выбора local/cloud запись не меняется. Это правило сохраняется и в API, и в migration UI.

## Phase 15 — кабинет преподавателя

Карточка ученика и просмотр кода доступны только после server-side проверки, что ученик состоит хотя бы в одной группе текущего подтверждённого преподавателя. Доступ к чужому ученику и чужой группе всегда отвечает `403`, даже если ID существует. Кабинет читает сохранённый progress, но не может его изменять. Начиная с Phase 17 счётчики курса и список практикумов генерируются из того же curriculum map, что и пользовательский контент.

## Phase 16 — администрирование

Статус пользователя меняется только через admin API. Блокировка и удаление сессий выполняются в одной транзакции: пользователь сразу теряет доступ к cloud account, а его данные, группы и progress остаются в базе. Инвайты не получают отдельного флага «отключено владельцем»: их уже безопасно отключает проверка активного статуса создателя и группы. Дерево преподавателей строится напрямую из `invited_by_user_id` без дополнительной таблицы.

## Phase 17–19 — импорт и полный curriculum

Upstream-контекст фиксируется commit и SHA-256 каждого использованного Markdown-файла в `content/python/source-manifest.json`; SHA-256 локальных авторских статей хранится там же. Порядок и области навыков задаёт `scripts/curriculum-map.mjs` по программе SK01–SK46.

Темы, которые в методичке собраны в одной главе, разделены по учебной цели: `if/else`, `elif` и составные условия; накопители и экстремумы; основы и изменение списков; строковый проход и серии; хранение, обход и пути в графах. Это устраняет главный дефект прежнего урока об условиях — слишком широкую область SK05–SK07. Для каждого урока генерируются две guided-задачи и checkpoint, а шесть практикумов содержат 92 задачи; каталог преподавателя генерируется из той же карты и показывает 49 уроков и 239 упражнений.
